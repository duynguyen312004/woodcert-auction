====================================================================
PROJECT SUMMARY - WOODCERT AUCTION PLATFORM
Last updated: 08/05/2026
====================================================================

Mục tiêu dự án:
WoodCert Auction là hệ thống đấu giá sản phẩm gỗ đã được kiểm định. Backend hiện được xây theo kiến trúc modular monolith bằng Spring Boot, MySQL, Redis, JWT, Cloudinary và WebSocket/STOMP. Frontend chưa bắt đầu code, nhưng backend contract đã đủ ổn để bước tiếp theo là thiết kế và triển khai FE theo từng vertical slice.

--------------------------------------------------------------------
1. TRẠNG THÁI TỔNG QUAN
--------------------------------------------------------------------

Backend hiện tại:
- Foundation, identity, media, catalog, appraisal, wallet/finance và auction runtime đã hoàn thành ở mức có thể dùng cho FE MVP.
- Auction runtime đã được bổ sung unit test và integration test bằng Testcontainers với MySQL 8 + Redis 7 thật.
- Full backend test suite đã pass:
  + .\mvnw.cmd "-Dtest=!WoodcertAuctionApplicationTests" test -> 192 tests pass.
  + .\mvnw.cmd "-Dtest=WoodcertAuctionApplicationTests" test -> 1 test pass.
  + .\mvnw.cmd clean test -> 193 tests pass.
- Không còn yêu cầu MySQL/Redis local cho test suite; Docker Desktop/Testcontainers là đủ.

Ước lượng tiến độ backend:
- Auction runtime: 95% cho phạm vi đăng ký, đặt cọc, bidding realtime, scheduler close, settlement deposit.
- Backend MVP trước fulfillment/order: khoảng 85%.
- Backend toàn sàn thương mại đầy đủ gồm fulfillment, shipment, dispute, admin vận hành: khoảng 70%.

Frontend:
- Chưa code.
- Đã tạo blueprint triển khai FE tại folder cùng cấp backend: woodcert-auction-fe/FE_IMPLEMENTATION.md.
- Khuyến nghị tiếp theo: bắt đầu FE theo vertical slice, không mở thêm backend domain lớn trước khi FE dùng được auction runtime.

2. BACKEND MODULES ĐÃ HOÀN THÀNH
--------------------------------------------------------------------

[X] Core Foundation
- Shared ApiResponse<T> và PaginationResponse<T>.
- GlobalExceptionHandler + ErrorCode tập trung.
- BaseEntity audit fields.
- Modular monolith theo package-by-feature.
- Validation DTO bằng Jakarta Validation.

[X] Security, Auth & Authorization
- JWT access token + refresh token rotation.
- Refresh token lưu DB để revoke/logout.
- Spring Security OAuth2 Resource Server dùng để validate JWT tự phát hành.
- JWT claim permissions được map sang GrantedAuthority.
- @CurrentUserId resolver inject user id từ JWT subject vào controller.
- Method security bằng @PreAuthorize.
- CORS hiện cho phép http://localhost:3000 và http://localhost:5173.

Auth endpoints chính:
- POST /api/v1/auth/register
- POST /api/v1/auth/login
- GET  /api/v1/auth/verify-email
- POST /api/v1/auth/resend-verification
- POST /api/v1/auth/refresh
- POST /api/v1/auth/logout

[X] Identity & Profile
- GET/PUT/PATCH /api/v1/users/me.
- POST/GET /api/v1/users/me/seller-profile.
- GET/POST /api/v1/addresses.
- GET /api/v1/locations/provinces.
- GET /api/v1/locations/districts?provinceCode=...
- GET /api/v1/locations/wards?districtCode=...
- User avatar upload/confirm/delete qua shared media service.

[X] Media & Cloudinary
- Backend tạo signed upload intent.
- Client upload trực tiếp lên Cloudinary.
- Backend confirm upload bằng mediaId + assetId.
- Domain tables chỉ giữ mediaId, không lưu raw URL làm source of truth.
- Cleanup job xử lý PENDING/PENDING_DELETE/orphan assets.
- Media flow đã dùng cho avatar, product images và appraisal proof images.

[X] Catalog & Product Workflow
- Seller tạo/sửa/xóa sản phẩm DRAFT.
- Seller submit appraisal: DRAFT -> PENDING_APPRAISAL.
- Appraiser xem hàng chờ kiểm định qua GET /api/v1/products.
- Product detail có access control theo seller/appraiser.
- Category read API và seed data.
- Product media APIs:
  + POST /api/v1/products/images/upload-intent
  + PUT  /api/v1/products/images/confirm

[X] Appraisal Workflow
- Appraiser submit appraisal report bất biến.
- Product chuyển APPRAISED hoặc REJECTED.
- Certificate code, verified material, origin, grade, estimated value, authenticity.
- Proof image media flow:
  + POST /api/v1/appraisals/images/upload-intent
  + PUT  /api/v1/appraisals/images/confirm
- POST /api/v1/products/{id}/appraise.

[X] Finance / Wallet
- Wallet có availableBalance và frozenBalance.
- Wallet transaction audit log.
- Internal operations: deposit, freeze, unfreeze, deductFrozen.
- Idempotent wallet mutations bằng operationKey.
- Optimistic locking cho wallet.
- Dev/test top-up path:
  + GET  /api/v1/wallets/me
  + GET  /api/v1/wallets/me/transactions
  + POST /api/v1/wallets/me/top-up

[X] Auction Foundation
- AuctionSession domain với WAITING, ACTIVE, CANCELED, ENDED_SUCCESS, ENDED_FAILED.
- Seller tạo auction cho product của mình đã APPRAISED.
- Một product không được có hơn một open session WAITING/ACTIVE cùng lúc.
- Public auction list/detail cho buyer/guest.
- Seller auction list và cancel WAITING session.
- reservePrice bị ẩn khỏi public detail.
- Redis overlay currentPrice/endTime cho ACTIVE list/detail, fallback DB snapshot.

Auction endpoints chính:
- GET   /api/v1/auctions
- GET   /api/v1/auctions/{id}
- POST  /api/v1/auctions
- GET   /api/v1/auctions/me
- PATCH /api/v1/auctions/{id}/cancel
- POST  /api/v1/auctions/{id}/register

[X] Auction Runtime
- AuctionParticipant + DepositStatus.
- Bid + BidStatus.
- Registration freeze deposit và insert participant FROZEN.
- Active late registration kiểm tra Redis runtime state và add bidder vào Redis set.
- Redis session hash + bidder set.
- Redis Lua atomic bid validation/update:
  + session active.
  + bidder registered.
  + seller self-bid blocked.
  + bidAmount >= currentPrice + stepPrice.
  + not expired.
  + current highest bidder không được tự nâng tiếp.
  + anti-sniper extend endTime khi bid sát giờ.
- Bid audit persistence bất đồng bộ/best-effort.
- DB snapshot sync best-effort sau bid accepted.
- WebSocket/STOMP events:
  + Connect: /ws-auction
  + Subscribe: /topic/auctions/{auctionSessionId}
  + Types: SESSION_ACTIVATED, NEW_BID, SESSION_ENDED
- Scheduler activation/close mỗi 5s khi enabled.
- Close settlement:
  + ENDED_FAILED nếu không đạt reserve, refund toàn bộ frozen deposits.
  + ENDED_SUCCESS nếu đạt reserve, deduct winner deposit, refund losers.
  + Per-participant settlement failure không chặn participant khác; participant lỗi giữ FROZEN để repair sau.
